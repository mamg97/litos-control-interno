# LITOS project context

Updated: 2026-09-18

## Purpose

LITOS is the workshop's internal control system. It consolidates authorized Gmail intake, private Drive documents, the operational master, draft/final invoice files, historical reconciliation and a sanitized public dashboard.

## Production architecture

```
Authorized client Gmail intake
        ↓
Private Google Drive order folders
        ↓
PEDIDOS LITOS (private operational master)
        ↓
Python / GitHub Actions
   ├─ handwriting enrichment
   ├─ draft generation
   ├─ folder organization
   ├─ invoice/albarán synchronization
   └─ sanitized public-feed generation
        ↓
GitHub Pages static dashboard
```

Google Apps Script is no longer a production dependency and its legacy source is not kept in the public repository.

## Schedules

- M3+M4: 07:07, 11:07, 15:07 and 19:07 Europe/Madrid.
- M2 Draft Sync: approximately every 15 minutes at :05, :20, :35 and :50.
- M6 and M7 bridge from successful scheduled Draft Sync runs.
- M5 folder organizer: daily scheduled production run.

## Source of truth

`PEDIDOS LITOS` is authoritative for operational reporting.

The website reads only a sanitized static feed generated by M7. It does not traverse private Drive or call Apps Script at runtime.

## Private client identity

The recurring client's legal identity belongs only in the hidden private-master sheet `Configuracion privada`.

The public repository must never contain the client's real name, address or sender email. Draft generation reads the private profile at runtime and still renders the legally/operationally required client block in private XLSX files.

## Historical reconciliation

Historical XLS/XLSX enrichment follows these safeguards:

- validate internal order number, not file name alone;
- reject/annotate impossible dates;
- fill missing fields without blindly replacing authoritative values;
- preserve ambiguous cases for review;
- record provenance in the master.

PVP and estadillo semantics live in `BUSINESS_LOGIC.md`.

## Public-repository privacy

Use only neutral roles in source, docs, workflow names and logs:

- workshop owner
- authorized sender
- client / external account
- private running account / estadillo

Never commit personal names, postal addresses, private email addresses, OAuth credentials, tokens or private document contents.
